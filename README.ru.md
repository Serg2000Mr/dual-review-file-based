# Dual Review File Based

Агент, который написал план или код, при повторной проверке может сохранить собственные ошибочные допущения. Кросс-ревью другой моделью даёт независимый взгляд: проверяющий заново изучает требования и реальные файлы, ищет ошибки, пропуски и лишнее усложнение. Разные модели могут замечать разные проблемы, поэтому такая проверка помогает выявить то, что автор пропустил.

Навык организует полный цикл: один агент выполняет задачу, второй проверяет результат, автор проверяет замечания и вносит обоснованные исправления, затем проверяющий изучает обновлённые файлы. Это позволяет довести замечания до проверенного результата, а не остановиться на списке предложений.

Для кросс-ревью выбирайте разные модели, а не только разные приложения: название Codex, ZCode или Claude Code само по себе не определяет используемую модель. Проверка той же моделью в отдельном чате тоже поддерживается — она даёт отдельный контекст, но не разнообразие моделей.

Эти навыки разделяют две роли: инициатор ведёт задачу и вносит исправления, независимый проверяющий изучает результат. Названия агентов не определяют роли: подходят Codex → Codex, Codex → ZCode, Claude Code → Codex и другие сочетания. Оба работают с общим каталогом проекта; по умолчанию пользователь один раз передаёт задание проверяющему. MCP-сервер и запуск через CLI не требуются.

| Пример установки | Каталог навыка | Среда |
|---|---|---|
| Claude Code | `claude-code/` | Скрипт ожидания для PowerShell или Bash |
| Codex | `codex/` | Windows PowerShell 5.1 |

Названия каталогов, навыков, заголовки рецензий и части имён файлов `claude`/`codex` сохранены для совместимости; они не ограничивают выбор агентов. Комплект выбирают по среде выполнения и возможностям приложения. У комплектов разные имена файлов ролей и вспомогательные скрипты. Устанавливайте их отдельно; не смешивайте файлы и не переносите между ними активную сессию.

## Быстрый старт

### Установка навыка с управлением сессией в Codex

Скопируйте содержимое каталога `codex/`, включая `tests/`, в `.agents/skills/claude-dual-review-file-based/` вашего проекта:

```powershell
New-Item -ItemType Directory -Force .agents/skills/claude-dual-review-file-based
Copy-Item codex/* .agents/skills/claude-dual-review-file-based/ -Recurse -Force
```

Попросите Codex применить `$claude-dual-review-file-based` к задаче или плану. Он сохранит готовое задание для независимого проверяющего. Передайте его выбранному проверяющему — например, другому чату Codex или ZCode — один раз; последующие раунды продолжаются в той же сессии.

Вариант для Codex содержит управление состоянием сессии, проверку протокола и публикацию рецензий без появления частично записанного итогового файла. После прерывания сохраняются привязка к чату, область проверки, число раундов и способ передачи задания. Для принятого замечания нужны реальные изменения файлов и запись результата проверки до следующего раунда. Изменение контрольной суммы само по себе не доказывает правильность исправления. Исправления вносит инициатор; проверяющий записывает только материалы ревью.

Чтобы узнать состояние существующей сессии:

```powershell
& '<каталог-навыка>/review-session.ps1' -Action status -ProjectRoot '<проект>' -ThreadId '<настоящий-id-чата>'
```

Если задана переменная `CODEX_THREAD_ID`, скрипт использует её автоматически. Он возвращает следующее действие и запрещает преждевременное завершение. Итоговые статусы в `final.md`: `approved`, `failed`, `limit`, а при явной отмене или технической остановке — `cancelled` и `stopped`. Инструкции и файлы ревью написаны по-английски; итоги в чате — по-русски.

Обработчики событий приложения необязательны и автоматически не устанавливаются. Зависимости от Serena и навыков конкретного проекта нет; соблюдайте правила проверяемого проекта.

При ручной передаче задания в Windows появляется постоянное окно с названием текущего проекта и задачи. Закрытие окна не означает, что проверяющий взял задание: это подтверждает только файл начала проверки.

### Исходный комплект инструкций: пример установки для Claude Code

Скопируйте весь каталог `claude-code/` в каталог навыков проекта:

```bash
mkdir -p .claude/skills/codex-dual-review-file-based
cp claude-code/* .claude/skills/codex-dual-review-file-based/
```

Затем вызовите в Claude Code:

```text
/codex-dual-review-file-based <описание задачи> [путь/к/плану.md] [max_rounds=5]
```

Инициатор создаст первый раунд и один раз покажет задание выбранному проверяющему. Следующие раунды проверяющий подхватывает в той же сессии; повторно передавать ему промпт не требуется.

## Как работает протокол

Каждая сессия находится в абсолютном каталоге `<корень_проекта>/.dual-review/<session_id>/`. Если инициатор запущен в отдельном рабочем дереве Git, сессия остаётся именно в нём.

```text
R1-01-round-start.md     <- Инициатор записывает контракт проверки
R1-02-codex-claimed.flg  <- Проверяющий забирает раунд
R1-03-codex-review.md    <- Проверяющий записывает рецензию
R1-04-claude-claimed.flg <- Инициатор обрабатывает результат
final.md                 <- Инициатор фиксирует итог сессии
```

Файлы начала раунда и рецензии содержат машиночитаемый блок JSON и пояснение для человека. Инициатор проверяет каждое замечание как гипотезу, вносит принятые изменения до открытия следующего раунда, а отклонённые замечания сопровождает доказательствами.

Сессия завершается статусом:

- `approved` после `APPROVED`;
- `failed` после редкого вердикта `REJECTED`;
- `limit` при достижении `max_rounds`.

Сам по себе `APPROVED` не завершает сессию: признаком завершения служит `final.md`.

## Гарантии протокола

- Файлы сессии только добавляются: протокольные файлы не перезаписываются и не удаляются.
- Абсолютные пути к `SESSION_DIR`, промпту рецензента и скрипту ожидания исключают смешение основного checkout и рабочего дерева.
- Сигнальные `.flg`-файлы позволяют после прерывания восстановить состояние по файлам, а не по истории чата.
- Область проверки фиксируется в первом раунде и не меняется между раундами.
- Поля JSON задают стабильный контракт для вердикта, серьёзности, уверенности, доказательств и идентификаторов замечаний.
- Отсутствующий или повреждённый JSON считается восстанавливаемой ошибкой протокола; агент не пытается угадать результат по свободному тексту.

## Окружение

Claude Code и Codex должны иметь доступ на чтение и запись к одному каталогу проекта. Навык работает при проектной и глобальной установке, потому что промпт и скрипты ожидания определяются относительно реально загруженного `SKILL.md`.

Используйте вспомогательный файл для своей среды:

- `wait-for-review.ps1` — Windows и PowerShell;
- `wait-for-review.sh` — macOS, Linux или Git Bash.

Оба скрипта из `claude-code/` принимают абсолютный каталог сессии, проверяют номер раунда, используют адаптивный опрос, возвращают компактный результат JSON и завершаются по настраиваемому тайм-ауту.

Комплект `codex/` требует Windows PowerShell 5.1 и содержит собственный `wait-for-review.ps1`. Проверяющий ожидает следующий раунд или итог с `-TimeoutSec 0`; ожидание инициатора по умолчанию ограничено одним часом. Тайм-аут не означает одобрение. Завершите активные сессии той версией навыка, которая их создала, прежде чем заменять установленные файлы.

## Проверки

Из корня репозитория в Windows:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File codex/tests/run-tests.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File codex/tests/session-tests.ps1
```

Проверяются ошибочные рецензии, запрет перезаписи, прерванная запись, ожидание, исправления и одобрение, изоляция чатов, восстановление, отмена и предел раундов. Проверки используют временные файлы и не запускают внешнего проверяющего. Они не подтверждают работу обработчиков в приложении или полный цикл с настоящими моделями.

## Проектные решения

- **Отдельный контекст и независимая проверка.** Второй агент полезен тем, что не обязан сохранять слепые зоны инициатора.
- **Замечания считаются гипотезами.** Инициатор принимает, отклоняет или исправляет каждое замечание с явной аргументацией; предложения рецензента не являются командами.
- **Начало раунда является контрактом.** Заявления о выполненных изменениях должны соответствовать реальным файлам, перечисленным для проверки.
- **Источником истины служат файлы.** После перезапуска агент продолжает работу по `.dual-review/<session_id>/`, а не восстанавливает состояние из чата.

## Структура репозитория

```text
codex/
  SKILL.md              # Инструкции инициатора Codex
  review-session.ps1    # Состояние сессии и цикл исправлений
  protocol-file.ps1     # Проверка и публикация файлов
  reviewer-prompt.txt   # Инструкции независимого проверяющего
  wait-for-review.ps1   # Скрипт ожидания для Windows
  tests/                # Проверки протокола и сессии
claude-code/
  SKILL.md              # Исходные инструкции инициатора
  reviewer-prompt.txt   # Инструкции независимого проверяющего
  wait-for-review.ps1   # Скрипт ожидания для Windows
  wait-for-review.sh    # Скрипт ожидания для Bash
docs/
  review-findings.md    # Историческая самопроверка исходного протокола
```

## Ограничения

- Скрипт управления сессией относится к Windows-комплекту `codex/`. Исходный комплект `claude-code/` сохраняет отдельный процесс, управляемый инструкциями.
- Оба агента должны сохранять доступ к одному проекту или рабочему дереву до завершения сессии.
- Файловый опрос намеренно прост и может заметить переход через несколько секунд.
- По умолчанию сессия ограничена пятью раундами.
